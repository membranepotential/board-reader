# The dumb-camera phone (/camera) and its control page (/control)

- Push the control channel over its sockets (`/cameras/{device_id}` for the phone, `/cameras` for the control UI's camera list, `/boards/{id}/control` for each control page) and never add a poll or a per-message HTTP endpoint, because polling cost about eight requests a second, each logged twice, and delayed every change by up to a poll; keep the frames on `/ingest`, whose header/JPEG pairing, recording and replay every edge relies on. Keep `CameraRegistry` the only holder of the state and post to each socket through its `Mailbox` (latest message per type), never an unbounded queue, because every message is a snapshot and a slow page must not make the node buffer.
- Make a camera's board id its device id (a UUID the phone or edge makes once), never a number the node hands out and never the phone's URL, because with `board=phone` as everyone's default a second phone silently streamed into the first one's board, and an assigned `board-N` went to the next new phone after a forget, which took three guards to keep apart. Keep `DeviceId` a subset of `CameraBoardId` (starts with a letter or digit, one plain URL path segment, up to 64), because the per-board routes carry the board id and a `/` makes `/boards/{id}/control` unreachable.
- Give every camera a name when it is first seen: the lowest `board-N` no other camera is called (`CameraRegistry._default_name`), persisted and renamable like any name, and show the name everywhere in the UI with the id only as small secondary text, because the id is a UUID nobody can read. Make a rename set the name (`CameraName`, unique among the known cameras and never another camera's board id) and nothing else, and a rename to `None` a default name again, because a rename that moved the board id (the first D18) split one game across two ids and restarted the live card with an empty PGN.
- Send the names to the live page as one `NamesMessage` snapshot through `PositionHub.set_names` (replayed first to a new subscriber once any camera has a name), never as a field on every position event, and relabel the card in place keyed by board id, because the event is the read's and is recorded, and a card keyed by anything a rename changes is rebuilt and loses its `GameDecoder`.
- Decide which `/ingest` frames a board id takes in `CameraRegistry.ingest_refusal` (pure, unit-tested) and only call it from the `/ingest` handler, counting refusals in `ingest.not_owned` and `frames_refused`: a camera's board id takes frames from that device only, a device the node does not know is refused, and a frame without a device id is taken only under an id no camera holds, because the Python `feed --board X` and replays carry no device id and must keep working, while a stale page must never stream into another camera's board. Drop `device_id` in `RecordedFrame.frame()`, because a replay is not the camera that recorded it.
- Forget only a disconnected camera, drop its name and config, and release its board everywhere the node keeps per-board state (`FrameIngest.forget`, the retained raw frame, `PositionHub.forget`) through the registry's `on_forget`, and publish nothing from a read of a forgotten board that was already running, because the node otherwise holds about 2 MB per camera ever seen, and a late event would put the forgotten camera back on the live page. The device, if it comes back, is a new camera under the same board id with a fresh default name.
- Keep one socket per device: post `replaced` to the older one and close it explicitly in `sockets.deliver` (`ws.close`), and make the phone stop for good on `replaced` (no reconnect), because a handler that only returns left Starlette's test socket open and the test hung, and two pages of one phone that both reconnect take the link from each other forever. Pass the `PhoneLink` to `report`/`preview`/`disconnect_phone`, which ignore a replaced one, so its late messages change nothing.
- Key `/control`'s cards by device id (which is the camera's board id; `CameraEntry` has no separate `board_id`) and the live page's cards by board id, and label both by name, sorting the live cards by name (`board-2` before `board-10`), because a card keyed by the name is rebuilt on a rename and loses its `GameDecoder`, and the random ids give no useful order.
- Run a stream added on `/control` as a `board-reader-edge camera` subprocess started by command name (`control/streams/command.py`: `BR_EDGE_COMMAND`, else the console script), never by importing `board_reader_edge`, because the two nodes meet only on the wire (`tests/test_layer_separation.py`). Start it with `start_new_session=True` and stop it by its process group (`os.killpg`), and keep the stream's device id in `streams.json`, writing the edge's `--state` file from it before every start, because a plain `terminate()` left the edge's children running (the orphan test fails without `killpg`), and the device id is the stream's board id, so a restarted stream keeps its board and name. Forget a removed stream's camera only after its socket closed, because `CameraRegistry.forget` refuses a connected camera.
- Spell device ids in tests with non-hex letters (`kitchen-phone-id`), never a real UUID, because `tests/test_commit_refs.py` reads every run of 8+ hex characters in a tracked file as a commit citation and fails `make test`.
- Run a socket handler's loops in an `asyncio.TaskGroup` (`sockets.until_first_ends`), never `asyncio.wait` plus a hand-rolled cancel and `gather`, because the server and Starlette's test client cancel the handler from outside at any moment, and the hand-rolled teardown turned that into a `CancelledError` that failed three socket tests under `make test` load while they passed alone.
- Build a value before an optional call inside a Svelte `$effect` (`const now = report; link?.report(now)`), never `link?.report({ ...state })`, because optional chaining skips evaluating the argument while `link` is null, so the effect reads no state on its first run, tracks nothing and never runs again; the phone then sent one report and went silent.
- Keep the phone's last config when its control link drops and re-send the report on every reconnect (`CameraLink` resets what it sent on open), because the node pushes the config again on connect but only hears a report the phone sends.
- Record what the phone asked the camera for (`Capture`: lens label + resolution) before the `getUserMedia` call, and let `nextCapture()` compare the config against that, not against what opened, so a lens that refuses is tried once rather than on every pushed config. Re-check it (`reconcileCapture`) on every config, when the camera first goes live and when the lens list changes, because a config is pushed once and a lens label the phone could not resolve yet must be tried again once it can.
- Choose a lens by opening any camera first, then `enumerateDevices`, and persist the choice by label; stop the outgoing tracks before requesting the next lens, because iOS shows labels only after a `getUserMedia` call, regenerates deviceIds per session, hands out one camera at a time and has no `zoom` capability.
- Keep the three recovery layers working together: track `ended`/`mute`/`unmute` listeners (guard `stream !== next`, since a replaced lens's tracks end too), `visibilitychange`/`pageshow`, and the `video.currentTime` watchdog (`noteFrameClock`). The visible handler must reset the clock itself (`freshFrameClock`), because iOS suspends `setInterval` in the background; serialize every `openCamera` through one promise queue and keep `recoverCamera`'s in-flight guard, because two interleaved opens stop each other's tracks and the loser keeps the camera claimed.
- Make every WebSocket handler close over its own socket and return when a newer socket replaced it (`if (socket !== this.socket) return`), because a stale socket's close otherwise nulls the live connection and spawns a duplicate. Compute anything derived from mutable UI state before the first `await` in the send path, and name bursts from a never-reset counter, not from seq, because seq advances only on frames actually sent.
- Snap crop edges to integer units of 1/10000 (`lib/control/crop.ts`) and derive `x` and `w` from them, because with float edges `x + w` can land a hair past 1 and the node's `CropRect` (`x + w <= 1`, `w >= MIN_CROP_SIDE`) refuses the save.
- Size a picture wrapper in JS (`k = min(box.w/src.w, box.h/src.h)`) and put the image and its overlay inside it, never `object-fit: contain` plus a coordinate-conversion helper, because `contain` letterboxes inside the element, so every touch needs a second coordinate space and a mistake there sends wrong geometry while the preview still looks right (`CropEditor.svelte` does it this way).
- Persist the configs and the names (`{"boards", "names"}`, both keyed by device id; the names list the known cameras) only through `BR_CAMERA_CONFIG` (set by `cli.cmd_serve`, read in `CameraRegistry()`), write the whole file as tmp + `os.replace`, and on load accept the file in full or ignore it with a WARNING, because a half-applied file would push a stale crop or `streaming: true` to the phone after a restart, or give one name to two cameras. Keep loading the older shapes: a file with only `"boards"` (before the device ids), and a file with a `"cameras"` table (device -> `board-N`, before the board id was the device id), which loads migrated in `persistence._from_board_numbers` (each config moves to its device id; an unnamed camera is named after its old `board-N`), because the operator must still read the same label after the update. Drop a saved config no camera holds at load with one INFO line, because the old shared `phone` config would otherwise wait for any camera that comes to hold that id.
- Take the board direction's running angle as the median of the latest reads with every offset wrapped around the newest read, never a plain mean or a median of raw degrees, because the angle wraps at ±180 (White at the top reads as both 179 and −179) and one hand-occluded read would move a mean. Reset the settled angle only on a reframing config (crop, lens, resolution), not on a streaming toggle, or stopping and starting the stream would hide a camera that moved meanwhile.
- Push the node's own Auto-frame crop through `CameraRegistry._set_config`, never `configure`, and treat every crop change that arrives through `configure` (a `/control` page) as drawn by hand, switching Auto-frame off, because `configure` cannot tell who changed the crop: an Auto-frame push through it switched Auto-frame off at once and the camera was never re-framed.
- When a newer socket of one device replaces the older, step the controller with `Disconnected` before `CameraRegistered` (`connect_phone`), because the older socket's in-flight `send_full_frame` can never be answered, and the controller holds every new request behind it until the 15 s timeout: a reloaded phone waited 15 s to be framed (a router test took 15 s).
- Answer `send_full_frame` with the `full_frame` header and its JPEG back to back on the camera socket, with no preview between them (`CameraLink.sendFullFrame` on the phone, `CameraLink._write` on the Python edge), and answer only the latest request, because the node takes the next binary message after a header as that full frame and every other binary as a preview. A camera not live yet keeps the request and answers when its first frame arrives.
- Keep the phone's previews on while Auto-frame watches the camera (`watching`), not only while a `/control` page is open (`CameraRegistry._previews_wanted`), because drift is detected on the previews: with previews tied to `/control`, a camera nobody watched was never re-framed.
