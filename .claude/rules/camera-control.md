# The dumb-camera phone (/camera) and its control page (/control)

- Push the control channel over the two per-board sockets (`/boards/{id}/camera` for the phone, `/boards/{id}/control` for each control page) and never add a poll or a per-message HTTP endpoint, because polling cost about eight requests a second, each logged twice, and delayed every change by up to a poll; keep the frames on `/ingest`, whose header/JPEG pairing, recording and replay every edge relies on. Keep `CameraRegistry` the only holder of the state and post to each socket through its `Mailbox` (latest message per type), never an unbounded queue, because every message is a snapshot and a slow page must not make the node buffer.
- Run a socket handler's loops in an `asyncio.TaskGroup` (`_until_first_ends`), never `asyncio.wait` plus a hand-rolled cancel and `gather`, because the server and Starlette's test client cancel the handler from outside at any moment, and the hand-rolled teardown turned that into a `CancelledError` that failed three socket tests under `make test` load while they passed alone.
- Build a value before an optional call inside a Svelte `$effect` (`const now = report; link?.report(now)`), never `link?.report({ ...state })`, because optional chaining skips evaluating the argument while `link` is null, so the effect reads no state on its first run, tracks nothing and never runs again; the phone then sent one report and went silent.
- Keep the phone's last config when its control link drops and re-send the report on every reconnect (`CameraLink` resets what it sent on open), because the node pushes the config again on connect but only hears a report the phone sends.
- Record what the phone asked the camera for (`Capture`: lens label + resolution) before the `getUserMedia` call, and let `nextCapture()` compare the config against that, not against what opened, so a lens that refuses is tried once rather than on every pushed config. Re-check it (`reconcileCapture`) on every config, when the camera first goes live and when the lens list changes, because a config is pushed once and a lens label the phone could not resolve yet must be tried again once it can.
- Choose a lens by opening any camera first, then `enumerateDevices`, and persist the choice by label; stop the outgoing tracks before requesting the next lens, because iOS shows labels only after a `getUserMedia` call, regenerates deviceIds per session, hands out one camera at a time and has no `zoom` capability.
- Keep the three recovery layers working together: track `ended`/`mute`/`unmute` listeners (guard `stream !== next`, since a replaced lens's tracks end too), `visibilitychange`/`pageshow`, and the `video.currentTime` watchdog (`noteFrameClock`). The visible handler must reset the clock itself (`freshFrameClock`), because iOS suspends `setInterval` in the background; serialize every `openCamera` through one promise queue and keep `recoverCamera`'s in-flight guard, because two interleaved opens stop each other's tracks and the loser keeps the camera claimed.
- Make every WebSocket handler close over its own socket and return when a newer socket replaced it (`if (socket !== this.socket) return`), because a stale socket's close otherwise nulls the live connection and spawns a duplicate. Compute anything derived from mutable UI state before the first `await` in the send path, and name bursts from a never-reset counter, not from seq, because seq advances only on frames actually sent.
- Snap crop edges to integer units of 1/10000 (`lib/control/crop.ts`) and derive `x` and `w` from them, because with float edges `x + w` can land a hair past 1 and the node's `CropRect` (`x + w <= 1`, `w >= MIN_CROP_SIDE`) refuses the save.
- Size a picture wrapper in JS (`k = min(box.w/src.w, box.h/src.h)`) and put the image and its overlay inside it, never `object-fit: contain` plus a coordinate-conversion helper, because `contain` letterboxes inside the element, so every touch needs a second coordinate space and a mistake there sends wrong geometry while the preview still looks right (`CropEditor.svelte` does it this way).
- Persist the configs only through `BR_CAMERA_CONFIG` (set by `cli.cmd_serve`, read in `CameraRegistry()`), write the whole file as tmp + `os.replace`, and on load accept the file in full or ignore it with a WARNING, because a half-applied file would push a stale crop or `streaming: true` to the phone after a restart.
- Take the board direction's running angle as the median of the latest reads with every offset wrapped around the newest read, never a plain mean or a median of raw degrees, because the angle wraps at ±180 (White at the top reads as both 179 and −179) and one hand-occluded read would move a mean. Reset the settled angle only on a reframing config (crop, lens, resolution), not on a streaming toggle, or stopping and starting the stream would hide a camera that moved meanwhile.
